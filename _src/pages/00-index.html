Run your first falsifiable decomposition, then defend it

A self-paced lab for researchers and students who know basic regression but have never run an Oaxaca–Blinder decomposition. You learn it on a real study: why children in households whose primary language is not English are less often reported to have an ADHD diagnosis.

Your goal

Reproduce the study's headline decomposition from the raw Census public-use file, within ±0.1 percentage points on every figure, and defend each modelling choice under questioning.

The headline you will reproduce: gap pp, explained pp, unexplained pp, n = children aged 6–17.

Seen different numbers elsewhere (n = 13,103, explained 8.91)? Both are correct reproductions; here is why.

The study's numbers can be produced with two codings of one covariate, caregiver mental health, when a second caregiver lives in the home but did not answer that question:

CodingnGap, pp (95% CI)Explained, pp (95% CI)Unexplained, pp
This lab's headline (reviewed coding): the child stays out of the model until every caregiver in the home has answered
Earlier coding (the figures in the brief this lab was built from): counted as “not poor” if the first caregiver answered; income averaged before fitting

The earlier coding guesses that an unanswered caregiver was in good mental health, which keeps more children in the model. The lab teaches the reviewed coding because it does not guess. The checkpoint below accepts either set and tells you which one you matched. Module 5 shows the step-by-step difference.

Read this on every results screen: “explained” means accounted for by differences in measured characteristics (composition). It never means “caused by”.

Why a specific, hard goal: people given specific, difficult goals tend to outperform those told to “do their best” (Locke & Latham, 2002). See Why this lab works this way.

Plan: two days, with a night's sleep in between

  1. Day 1 (core, about 5–6 hours): Modules 1–5 in order, then run the core program on your computer and enter your numbers below.
  2. Day 2 (about 6 hours): Exercise A (access-to-care gap, same file) and Exercise B (care navigation, pooled annual NSCH 2016–2025).

The hours are the builder's estimates; no learner has been timed.

Why split across days: spreading practice over sessions improves retention compared with massing it (Cepeda et al., 2006), and sleep after learning supports memory consolidation (Diekelmann & Born, 2010). The lab does not claim more than that; see the Why page for limits.

Checkpoint: did you reproduce the headline?

Run the core program in R or Python, then type your three numbers in percentage points. You do not need to download anything first: the program fetches the lab files (about 2 MB) and the Census public-use file (about 6 MB) by itself.

  • R or RStudio: paste this one line into the console and press Enter. Missing packages are installed for you.
    source("https://raw.githubusercontent.com/LuShiUCLA/decompose/main/programs/core/decomposition_lab_core.R")
  • Python 3.12 or later: download the lab as a zip file and unzip it. Open a terminal in the unzipped folder, then run pip install -r programs/requirements-lock.txt followed by python programs/core/decomposition_lab_core.py.

Prefer to look first? The programs, notes and run logs are in the lab's GitHub repository.

The run takes about a minute. It ends with a line such as SELF-CHECK: 131 PASS, 0 FAIL; your numbers are in the lines under "STEP 3". R saves its files in a folder named decompose-main inside its working directory; type getwd() to see where that is. More options are in the programs guide.

What you will be able to do

  1. Say in plain language what a decomposition shows and does not show, and why a logit decomposition does not add up on the probability scale while a linear-probability one does.
  2. Design a twofold Oaxaca–Blinder decomposition on survey data: grouping variable, reference coefficients, covariate blocks, variance estimator.
  3. Run it in Python and R on the real public-use file and diagnose a result that does not reproduce.
  4. Build checks that expose coding errors: a wrong skip rule, a wrong insurance variable, a subsetting mistake, a misreported n.
  5. Apply the same machinery to two new questions (the exercises).
