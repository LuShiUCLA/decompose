Sources and reproducibility

Where every number comes from, how to regenerate it, and how the lab's design brief was checked.

Get the programs

  • Repository (programs, data notes, run logs, review records): github.com/LuShiUCLA/decompose.
  • Download everything as one zip file: decompose-main.zip. The paths on this site, such as programs/core/…, are folders inside it.
  • How to run: the checkpoint on the home page (one line in R), or the programs guide.

Data

  • NSCH Longitudinal Cohort (NSCH-LC), 2024 public-use file, U.S. Census Bureau: data page (downloads) and survey page. The programs read the Stata file; the one line to edit is DATA_PATH at the top of each program. Checksums are in data-notes/.
  • Documentation used: the Methodology Report, the Source and Accuracy Statement, the Variable List and the guide to multiply imputed data.

How the numbers reach this page

  1. programs/core/decomposition_lab_core.py (and its R twin) read the public-use file and write core_results.json, a run log and a PASS/FAIL self-check.
  2. programs/build_lab_data.py copies those JSON files into lab/assets/lab-data.js.
  3. Every figure on every page is looked up in that file by name. No number in the page text is typed by hand.

The reference values the self-check compares against come from the project's earlier, reviewed analysis pipeline (logged run of 17 November 2026, re-run on 22 November 2026 with identical results). Copies of its output tables are in data-notes/logged_reference/; data-notes/make_reference_values.py turns them into reference_values.json.

The reference run on this page: Python , seed , bootstrap replicates.

How the design brief's figures were checked

Every figure the brief quoted (30 rows) was checked against the logged runs and the public-use file (data-notes/reconciliation.md has the full table).

  • The brief's decomposition reproduces exactly, intervals included (gap ; explained ; n ), with the method of the project's superseded first program: an earlier caregiver mental-health rule, income averaged over the six imputations in one fit, and a bootstrap without the Rao–Wu rescaling. The lab's headline uses the reviewed choices (n ; explained pp). Module 5 shows what each choice changes.
  • The brief's PSC means reproduce when the five items are summed only for children who answered all five; Census's released score counts an unanswered item as 0.
  • Three values reproduce but carry the wrong label (for example, 16.3% vs 6.0% is the 2024 follow-up, not Wave 1).
  • The brief's “earlier specification” (n 11,928) reproduces from the superseded program. Its all-ages figures reproduce there too, on 21,204 children; the brief’s n of 18,042 belongs to a different specification in the same run of that program. Neither is used.

How this lab was checked

  • Self-checks. Each program compares its own output with logged reference values and prints PASS or FAIL for every figure; the reference run passes all of them. The R and Python programs check each other.
  • Independent review. A separate reviewer, another AI agent that did not build the lab, examined the programs, data notes and pages in five rounds. The builder fixed each issue it raised. After round 5 there were no open issues. The builder made and checked the final round of fixes; the reviewer did not re-run them. Records: ISSUES.md, VERIFICATION_LOG.md and every round.
  • Beginner test. A test run in the role of a student new to decomposition led to the plain-language notes and the glossary added on 22 November 2026.
  • What is not public. The reference values come from the study's own analysis pipeline. Its output tables are in the repository (data-notes/logged_reference/); its code will be added after the study is published. The lab's own programs are complete without it.
